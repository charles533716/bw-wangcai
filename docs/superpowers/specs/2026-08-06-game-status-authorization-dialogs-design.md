# 游戏状态与站点授权弹窗设计

日期：2026-08-06

## 目标

将总控后台“资源管理 → 场馆管理 → 游戏列表”的“切换状态”“授权”“取消授权”改为参考截图的可操作弹窗，并保证游戏授权不超出所属场馆已授权站点范围。

## 范围

- 修改场馆管理共享模型、游戏列表组件、场馆取消授权联动和对应验证脚本。
- 不修改原独立游戏列表。
- 不修改钱包列表及其他资源管理页面。
- 游戏切换为维护中时继续写入维护日志。

## 站点与授权边界

- 站点目录通过现有 `src/api/site/site.js` 的 `listSite()` 获取。
- 游戏授权候选站点必须同时满足：站点存在于总站/站点列表、游戏所属场馆已授权该站点、游戏尚未授权该站点。
- 取消游戏授权只显示当前游戏已授权站点。
- 场馆取消某站点授权时，同步移除该场馆下所有游戏对该站点的授权，避免越权遗留。

## 游戏授权数据

- 游戏记录新增 `authorizedSiteCodes`，保存具体已授权站点 CODE。
- 游戏列表授权数由 `authorizedSiteCodes.length` 实时计算。
- 旧缓存中的数字 `authCount` 按游戏所属场馆的已授权站点顺序迁移，迁移数量不超过场馆授权范围。
- 新增游戏默认没有站点授权。

## 切换游戏状态弹窗

- 标题：切换游戏状态。
- 展示游戏名称，格式为“游戏名称 / 游戏CODE”。
- 状态单选：启用、维护中、停用。
- 提交实际变化后更新最后编辑人和最后编辑时间。
- 切换为维护中时追加维护日志；重复提交当前状态不重复写日志。
- 游戏状态不执行场馆账单模板结算费率校验。

## 游戏授权弹窗

- 标题：“游戏授权 - 游戏名称”。
- 筛选项：站点 ID/编号、站点名称、开始/结束站点 ID、数据库 ID。
- 筛选和重置行为与场馆授权弹窗一致。
- “全部”只作用于当前筛选结果。
- 未选择站点时禁止确定授权。
- 提交后合并站点 CODE、去重、更新授权数并持久化。
- 所属场馆没有授权站点时显示空状态。

## 取消游戏授权弹窗

- 标题：“取消游戏授权 - 游戏名称”。
- 字段和筛选规则与授权弹窗一致。
- 只展示当前游戏已授权站点。
- 确定后移除所选站点 CODE 并更新授权数。
- 未选择站点时禁止确定取消授权。

## 组件边界

- `GameList.vue`：负责三个游戏弹窗、读取站点目录和交互状态。
- `model.js`：扩展通用站点授权纯函数、游戏授权迁移及场馆取消授权向游戏级联清理。
- `VenueList.vue`：取消场馆授权时将共享状态传给级联清理函数，不改变现有弹窗布局。
- 父页面继续负责 localStorage 持久化。

## 验证

- 模型测试先失败后实现：
  - 游戏授权不得超出场馆授权范围。
  - 游戏授权去重、取消后授权数同步。
  - 场馆取消授权级联清理所属游戏授权。
  - 旧数字授权数迁移不超过场馆站点范围。
- 页面静态检查覆盖三个弹窗标题、游戏名称、三状态和站点筛选字段。
- 浏览器验证状态提交、维护日志、授权候选范围、筛选、全选、授权数变化和取消授权。
- 运行场馆管理模型、客户端资源、权限、菜单回归及生产构建。
