# 总控后台场馆管理设计

日期：2026-08-06

## 目标与范围

在总控后台“资源管理”中，于“站内信”下方新增“场馆管理”二级菜单。原有独立“游戏列表”菜单继续保留。本功能为浏览器本地 Mock 原型，不接入真实后端，不修改站点后台已有场馆管理页面。

场馆管理页面包含四个 Tab：场馆列表、游戏列表、钱包列表、维护日志。

## 页面结构

新增一个场馆管理父页面，负责 Tab 切换和共享数据模型。四个 Tab 使用独立组件，避免单文件承载所有列表、弹窗和操作逻辑。

共享模型统一管理场馆、游戏、钱包和维护日志，并使用带版本号的 `localStorage` 键持久化。模型版本变化时重建演示数据，避免旧结构污染页面。

## 场馆列表

筛选条件：

- 场馆名称，支持中文名、英文名和 CODE 模糊匹配。
- 场馆类型。
- 状态。
- 备注。
- 筛选和重置按钮。

列表字段：

- 序号。
- 场馆。
- 场馆 CODE。
- 场馆中文名称。
- 场馆类型。
- 场馆佣金比例。
- 最后更新时间。
- 游戏数。
- 授权数。
- 场馆状态。
- 备注。
- 操作。

游戏数为可点击操作，点击后切换到游戏列表 Tab，并自动筛选当前场馆。

操作包含详情、编辑、切换场馆状态、授权和取消授权。授权数在授权或取消授权后实时更新。切换为维护状态时写入维护日志。

新增场馆和编辑场馆共用弹窗。新增字段为：场馆 ID、场馆 CODE、中文名称、场馆类型、场馆钱包、场馆佣金比例、排序、备注。必填项为场馆 ID、场馆 CODE、中文名称、场馆类型、场馆钱包、佣金比例和排序；场馆 ID 与 CODE 必须唯一。佣金比例范围为 0 至 100，最多四位小数。弹窗显示说明：代理佣金结算计算场馆费用时，站点自定义费率优先，否则使用场馆默认费率。

详情弹窗只读展示完整场馆字段。编辑时场馆 ID 不允许修改，场馆 CODE 保持唯一性校验。

## 游戏列表

筛选条件：

- 游戏名称。
- 支持平台。
- 状态。
- 游戏场馆。
- 场馆类型。
- 游戏 CODE。
- 品牌。
- 筛选和重置按钮。

列表字段：

- 序号。
- 游戏名称。
- 游戏场馆。
- 场馆类型。
- 游戏 CODE。
- 支持平台。
- 排序。
- WEB 游戏图片。
- H5 游戏图片。
- 授权数。
- 游戏状态。
- 品牌。
- 创建人。
- 创建时间。
- 最后编辑人。
- 最后编辑时间。
- 操作。

操作包含编辑、切换状态、授权和取消授权。WEB/H5 图片使用现有图片上传组件，可上传、替换、预览和删除。

新增游戏弹窗包含游戏名称、游戏场馆、游戏 CODE、支持平台、排序、WEB 游戏图片、H5 游戏图片、品牌和状态。游戏 CODE 必须唯一，场馆类型由所选场馆自动带出。

批量新增游戏使用可动态增删的表格弹窗，每行包含游戏名称、场馆、游戏 CODE、支持平台、排序和品牌；提交前校验行内必填、CODE 唯一以及与已有数据不重复。

游戏切换为维护状态时写入维护日志。场馆列表的游戏数根据游戏数据实时统计。

## 钱包列表

筛选条件：钱包名称、是否直投，以及筛选和重置按钮。

列表字段：序号、钱包名称、钱包 CODE、钱包场馆、是否直投、授权数、操作。

操作包含新增钱包、编辑、锁定钱包、解锁钱包、删除和站点状态调整。锁定与解锁按钮根据当前状态互斥展示或禁用，删除前二次确认。

新增和编辑钱包弹窗包含钱包名称、钱包 CODE、关联场馆、是否直投。钱包 CODE 必须唯一，至少关联一个场馆。

站点状态调整使用弹窗选择演示站点并设置启用或停用状态，提交后显示成功反馈。钱包授权数随站点状态调整结果更新。

## 维护日志

筛选条件：维护场馆/游戏名称，以及筛选和重置按钮。

列表字段：序号、维护场馆、维护游戏、维护时间、操作人、操作时间、维护原因。

日志由场馆或游戏切换维护状态时自动追加，不提供编辑和删除，保证操作追踪语义。初始 Mock 数据覆盖平台维护、维护时间到期和提前结束维护等场景。

## 数据、分页和状态

四个 Tab 使用同一共享模型，避免场馆、游戏、钱包和日志统计不一致。列表使用本地筛选和分页，筛选后总数取过滤结果长度，删除后总数同步减少，当前页越界时回退到有效页。

初始数据至少覆盖八类场馆、启用/停用/维护状态、不同平台组合、直投与非直投钱包、已授权和未授权场景。演示图片复用项目内已有占位资源。

## 菜单与权限

新增总控路由 `/resources/venueManagement`，菜单标题为“场馆管理”，放在资源管理的站内信下方。原有 `/resources/gameList` 继续保留。

权限目录新增场馆管理页面及查看、新增、编辑、状态切换、授权、取消授权、删除和站点状态调整等原型操作节点。页面按钮使用一致的权限标识，避免权限树与实际按钮不一致。

## 错误处理与反馈

必填、唯一性、数值范围和关联关系在提交前校验。危险操作使用确认弹窗。成功操作显示明确提示；校验失败保持弹窗和当前输入，不丢失用户编辑状态。

## 验收与测试

- 模型检查：初始数量、唯一性、筛选、分页、场馆游戏数、授权统计、维护日志联动和持久化版本。
- 构建检查：Vue2 生产构建成功，`git diff --check` 通过。
- 浏览器检查：菜单位置、四个 Tab、筛选重置、分页、全部新增/编辑弹窗、状态切换、授权/取消授权、钱包锁定解锁删除、站点状态调整及维护日志新增。
- 回归边界：原独立游戏列表仍可访问；现有客户端资源配置和站点后台场馆页面不受影响。

## 非本次范围

- 真实后端接口、数据库和跨设备持久化。
- 截图中的哈希游戏、特别平台费率等额外 Tab。
- 批量授权、批量删除、批量维护等未在最终文字要求中明确的扩展操作。
- 修改或移除原有独立游戏列表。
