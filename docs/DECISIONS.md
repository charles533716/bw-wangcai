# 项目决策记录

## 产品与交付规则

### 1. 本项目定位为可交互需求原型

- 决策：优先实现页面、Mock 数据和关键交互，不默认开发真实后端。
- 原因：主要使用者是产品、研发和测试，目标是快速确认需求与交互。

### 2. 先本地验收，再按明确指令发布

- 决策：每轮修改默认只保留在本地；只有用户明确说“更新到 GitHub”时才提交和推送。
- 原因：避免未验收布局进入公开演示地址。

### 3. 菜单以测试环境为准

- 决策：原型菜单与测试环境不一致时，按测试环境调整名称、顺序和显隐。
- 原因：研发与测试需要使用一致的信息架构核对需求。

### 4. 总控后台与站点后台权限目录相互独立

- 决策：总控角色读取总控菜单权限；站点权限管理、站点角色和站点账号权限预览只读取站点后台菜单。
- 原因：两套后台的菜单和授权边界不同，混用会导致越权和错误展示。

### 5. 站点权限采用上级约束模型

- 决策：总控授权站点，站点角色只能在授权范围内分配，账号通过角色继承权限。
- 原因：保证下级权限不超过上级授权范围。

### 6. 站点批量配置和权限复制采用统一覆盖

- 决策：当前勾选项覆盖所有目标站点，未勾选项同步回收，不做增量合并。
- 原因：覆盖结果明确，便于总控统一治理和审计。

## 技术方案

### 7. 保持 Vue 2 与 Element UI 技术体系

- 决策：继续使用现有 Vue 2 Options API 和 Element UI，不进行框架升级。
- 原因：项目为持续迭代原型，升级成本和回归风险高于收益。

### 8. 原型状态优先使用页面 Mock 和 localStorage

- 决策：不依赖真实接口的演示状态可由组件内数据生成，并在需要时使用 `localStorage` 持久化。
- 原因：保证原型独立运行和刷新后可继续演示。

### 9. 站点权限目录需要版本失效机制

- 决策：站点权限目录变化时，通过目录版本或签名使旧的本地授权数据失效并重建。
- 原因：避免新增菜单后仍读取旧授权快照，造成页面缺失。

### 10. GitHub Pages 使用专用构建

- 决策：发布使用 `npm run build:github`，公共路径固定为 `/bw-wangcai/`，同时生成 404 回退文件。
- 原因：Vue 单页应用在项目子路径和刷新深链接时需要正确资源路径及回退。

## 页面与交互决策

### 11. 蓝色文字代表可操作内容

- 决策：普通展示字段使用黑色或中性色；蓝色仅用于按钮、链接和可点击操作。
- 原因：减少用户对可点击性的误判。

### 12. 状态、筛选和表格布局优先保证可读性

- 决策：状态使用明确颜色区分；筛选项按常规标签加控件排列；宽表格使用横向滚动和必要冻结列。
- 原因：后台使用者以快速扫描、比较和重复操作为主。

### 13. Mock 数据必须符合业务规则

- 决策：不为了凑数量保留空白、重复或不合理数据；删除后总数可同步减少。
- 原因：错误示例会误导研发对字段含义和校验规则的理解。

### 14. 客户端资源配置固定为七个二级 Tab

- 决策：包含登录注册页、APP 下载页、合营计划、WEB 首页、WEB 二级下拉、APP/H5 首页、WEB 场馆详情页。
- 原因：这些入口对应已确认的客户端资源使用场景。

### 15. WEB 首页顶部类型不可重复占用

- 决策：八个位置从哈希、体育、真人、棋牌、电竞、彩票、电子、捕鱼中选择，已被其他位置占用的选项不可再选。
- 原因：防止首页导航出现重复类型。

### 16. WEB 二级下拉不包含 APP 下拉

- 决策：只保留八个场馆类型；每类可配置返水展示和动态场馆项，至少保留一项。
- 原因：APP/H5 已有独立配置页，避免职责重叠。

### 17. APP/H5 首页场馆配置采用分组表格

- 决策：八个场馆类型分别配置类型排序，类型下场馆配置名称、场馆排序和图片。
- 原因：同时满足类型顺序和类型内场馆顺序的配置需求。

### 18. WEB 场馆详情字段按场馆类型区分

- 决策：体育、电竞、棋牌、真人、彩票使用场馆名称图片、游戏图片、场馆文案；电子、捕鱼、哈希使用悬停前和悬停后图标。
- 原因：两类客户端展示方式不同，不能机械复用同一组字段。
- 状态：已按该规则实现并通过模型、构建和浏览器字段切换验收。
- 实现约束：上传字段必须在 `.vue` 模板中直接声明，不使用运行时字符串 `template` 子组件，确保当前 Vue 运行时构建能够正常渲染。

## 容易误解的问题

### 19. “本地打不开”通常不是业务代码错误

- 决策：先检查开发服务是否运行、端口是否监听和 URL 是否正确，再排查页面代码。
- 原因：历史上多数本地访问失败来自服务进程停止。

### 20. README 不是端口和部署配置的最终依据

- 决策：运行参数以 `package.json` 和 `vue.config.js` 为准。
- 原因：README 保留了上游模板说明，存在路径与端口过时问题。

### 21. “已有页面”不等于“已完成最终验收”

- 决策：进度记录需区分代码中已有、已浏览器验证和仍待验收。
- 原因：长周期原型可能已有结构，但仍存在布局、数据或交互细节未核对。

### 22. 客户端资源图片配置约束

- 登录注册页：WEB 端和 H5/APP 端 LOGO 各支持一张非必填图片；WEB 端背景图支持一张非必填图片，并支持 GIF。
- APP 下载页：LOGO、下载页背景图各支持一张图片；Android 和 iOS 展示图各最多六张并支持修改排序；Android 和 iOS 安装教程图各支持一张图片。
- 合营计划：WEB 端主图支持一张图片。
- 七个二级 Tab 使用紧凑字号，避免横向导航拥挤。
- 原因：这些数量、端别和格式约束均已由产品逐项确认，后续不能仅参考旧截图中的必填标记或字段名称。

### 23. APP/H5 首页已完成实现与验收

- 决策：APP/H5 首页已完成八类场馆分组、类型排序、场馆排序、单图上传、提交校验和重置快照，并通过浏览器交互与布局验收。
- 排序规则：类型排序必须为 1-8 的不重复整数；同类场馆排序必须为 1-N 的不重复整数。
- 图片规则：每个场馆必须配置一张 JPG、JPEG 或 PNG 图片，单张不超过 2MB，支持上传、替换、预览和删除。
- 重置规则：提交成功后保存当前组件会话快照；点击重置恢复最近一次成功提交的配置，未提交时恢复初始 Mock 数据。

### 24. 客户端资源配置统一采用会话快照重置

- 决策：七个二级 Tab 的保存/提交成功后更新当前会话快照，重置恢复最近一次成功保存的配置；首次保存前恢复初始 Mock 数据。
- 原因：原型暂无后端接口，快照方式可准确演示保存后继续编辑再撤销的预期行为，同时避免重置回硬编码旧数据。

### 25. 客户端资源配置权限继承站点配置页面

- 决策：客户端资源配置作为“站点配置”的一级 Tab，不新增独立路由权限或按钮权限码；现有上传、保存、重置等交互继承站点配置页面访问权限。
- 原因：当前权限体系按路由页面和显式 `v-hasPermi` 权限码生成，强行从按钮文案生成独立节点会产生没有后端权限码的伪权限。
- 原因：明确原型中的排序、图片完整性和撤销边界，避免静态占位或无响应按钮被误认为已完成功能。

### 26. 总控场馆管理使用四 Tab 共享本地模型

- 决策：资源管理下新增“场馆管理”，固定包含场馆列表、游戏列表、钱包列表和维护日志四个 Tab；原独立游戏列表继续保留。
- 数据规则：四个 Tab 共用带版本号的 `localStorage` 状态，场馆游戏数、授权数、钱包站点状态和维护日志实时联动。
- 边界：不复用站点后台的场馆授权组件，不修改真实接口；避免将总站资源资料与单站点授权配置混为同一数据维度。
- 菜单顺序：场馆管理固定紧跟“站内信”，并排在保留的原独立“游戏列表”之前。
- 缓存策略：场馆管理 Mock 状态使用独立 v2 版本键；模型字段或演示数据规则变化时通过版本迁移，避免旧缓存覆盖新规则。
